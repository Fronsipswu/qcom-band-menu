# Contributing

Contributions are welcome, and these guidelines keep the review process manageable for the maintainers.

## Open an issue first

If you want a new feature implemented, please open an issue first. You might already have a working example, and that is a good thing, so share it in the issue instead of opening a pull request right away. The maintainers can then discuss the idea there and decide whether the project should take it. Once the decision is positive, you can go ahead and open a pull request.

## Link the pull request to its issue

A pull request for a new feature needs to be linked to the related issue. This keeps the discussion in one place and makes it clear what the pull request is meant to solve.

## Work in a branch on your fork

Implement your feature in a new branch in your own fork of the repository. This lets the maintainers edit the pull request directly when a small correction is needed, instead of asking you to send a new one.

## One feature per pull request

Keep one feature per pull request. Please do not bundle several modifications or additions together. Big pull requests with many unrelated changes are hard to review and take much longer to get merged.

Quick bug fixes for existing features are still welcome as pull requests without an issue.

## Test before you submit

It is best practice to test your changes before submitting the pull request.

## Include screenshots

Please add screenshots to your pull request to show what changed. They make it much easier for the maintainers to see the result without building the app themselves.
